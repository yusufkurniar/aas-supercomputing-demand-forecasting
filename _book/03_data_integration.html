4.1 Purpose

The purpose of the data integration stage is to combine the different datasets collected for the project into a structured analytical dataset while preserving their original values, units, scope and provenance.

The source datasets cover different reporting periods, levels of granularity and data structures. Integration is therefore required to align common identifiers such as analytical year, facility, computing system, resource type and Field of Research before the data can be analysed together.

At this stage, integration focuses on organising and linking the available information rather than forcing observations into common units or classifications. Differences in naming, classification and compute units are addressed subsequently through data standardisation and conversion.

Where datasets cannot be combined directly because of differences in scope or granularity, those distinctions are retained explicitly rather than assuming equivalence.

4.2 Main Datasets

The integration process combines several datasets covering 2014 - 2026, with different analytical roles.

The core HPC datasets include:

  • yearly HPC demand and allocation source workbooks,
  • Field of Research composition data, and
  • HPC system and capacity information.

Supporting datasets include:

  • research funding data, and
  • research workforce and research activity data.

The core datasets provide the historical evidence used to construct measures of requested compute, allocated compute and disciplinary composition. Supporting datasets are retained as contextual or candidate explanatory variables for later analysis and modelling.

Because these datasets differ in temporal coverage, granularity and reporting scope, they are not merged indiscriminately. Integration is performed only where suitable common identifiers and compatible levels of aggregation are available.

Where annual demand or allocation measures are not directly available, derived or proxy values are constructed later from the integrated source evidence using explicitly documented assumptions. These selected annual measures are subsequently assembled into a separate summary dataset for modelling.

4.3 Yearly Source Integration

The detailed yearly source files are integrated before constructing the annual modelling summary.

For the HPC demand and allocation data, each yearly workbook contains multiple types of evidence. The integration therefore preserves the different analytical levels rather than reducing each workbook immediately to a single annual value.

Three recurring components are retained:

  • Project_Allocations, containing project- or allocation-level records,
  • Context_Metrics, containing reported or derived annual and contextual measures, and
  • Resource_Envelope, containing information on available resources and system-level capacity.

Field of Research data are integrated separately from the yearly FoR_Composition sheets.

The source filename and source period are retained during integration so that each observation remains traceable to its original yearly workbook. The resulting integrated tables form the evidence base from which annual summary measures are selected or derived later.

get_source_period <- function(path) {

  filename <- basename(path)

  years <- str_match(
    filename,
    "(\\d{4})_(\\d{2})"
  )

  paste0(
    years[, 2],
    "/",
    years[, 3]
  )
}

get_end_year <- function(source_period) {

  end_year <- str_extract(
    source_period,
    "(?<=/)\\d{2}$"
  )

  2000 + as.numeric(end_year)
}

Each yearly demand and allocation workbook contains several recurring worksheets. The same set of yearly workbooks is therefore used to extract each analytical component separately.

4.3.1.1 Integrate Context Metrics

Demand and allocation context metrics are combined across the yearly workbooks.

These records contain annual or supporting measures used to interpret requested compute, allocated compute and related demand-allocation relationships.

Code 
context_metrics <- map_dfr(
  demand_files,
  function(file) {

    read_excel(
      file,
      sheet = "Context_Metrics"
    ) |>
      mutate(
        source_file = basename(file),
        source_period = get_source_period(file)
      )
  }
)

4.3.1.2 Integrate Project Allocations

4.3.1.4 Align Analytical Year

A common analytical year is created to align observations across the different yearly source tables. The ending year of each source period is used as the common reference year where a consistent NCMAS or allocation year is not available.

Code 
context_metrics <- context_metrics |>
  mutate(
    year = get_end_year(source_period)
  )

project_allocations <- project_allocations |>
  mutate(
    year = coalesce(
      suppressWarnings(as.numeric(ncmas_year)),
      suppressWarnings(as.numeric(allocation_year)),
      get_end_year(source_period)
    )
  )

resource_envelope <- resource_envelope |>
  mutate(
    year = coalesce(
      suppressWarnings(as.numeric(ncmas_year)),
      suppressWarnings(as.numeric(allocation_year)),
      get_end_year(source_period)
    )
  )

4.4 Annual Demand and Allocation Summary Construction

The annual demand and allocation summary is constructed after integration of the detailed yearly source evidence.

The existing manually assembled summary is retained temporarily as a reference for reconciliation rather than treated as an independent source of data. Each annual requested and allocated compute value is checked against the integrated Context_Metrics, Project_Allocations and Resource_Envelope evidence.

Where a directly reported comparable annual value is available, that value is preferred. Where it is not available, a derived or proxy value may be constructed from the integrated evidence using an explicitly documented assumption.

Code 
current_summary <- read_excel(
  file.path(clean_path, "demand_allocation_data.xlsx")
) |>
  mutate(
    year = get_end_year(source_period)
  )
Code 
demand_allocation_evidence <- context_metrics |>
  filter(
    str_detect(
      metric,
      regex(
        "request|demand|allocat|fulfil|oversub|capacity|available",
        ignore_case = TRUE
      )
    )
  ) |>
  select(
    year,
    source_period,
    metric,
    value,
    unit,
    scope,
    source,
    source_url,
    notes
  ) |>
  arrange(year, metric)
Code 
reconciliation_check <- current_summary |>
  select(
    year,
    source_period,
    requested_compute,
    allocated_compute,
    requested_value_type,
    allocated_value_type
  ) |>
  left_join(
    demand_allocation_evidence,
    by = c("year", "source_period")
  ) |>
  arrange(year, metric)

4.5 Integration Considerations

Several issues need to be considered when integrating the datasets:

  • reporting periods are not always consistent across sources
  • Field of Research classifications have changed over time
  • institution names may be reported differently
  • CPU and GPU resources are reported using different units
  • some historical demand values are directly reported while others are estimated or derived
  • the level of detail available varies across years

These differences are retained and documented rather than assuming that all observations are directly comparable.

4.6 Output

The output of this step is an integrated dataset that retains the original source information while providing a common structure for subsequent data standardisation and conversion.
